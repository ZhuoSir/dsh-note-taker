# 需求规格：meeting-agent-import

## 背景与目标

用户 2026-11-10 的原话是「会话里上传，或者引用本地文件」+「会话里告诉他，帮我生成会议纪要之类」——
想要的不是界面上的导入按钮，而是**把这件事交给会话里的 agent**。

现在插件有 6 个工具（`meeting_record_start/stop/transcribe/minutes/list/status`），
但**没有一个能「把一段已有音频交给插件」**。所以 agent 收到音频后无路可走：
它不能自己转写（本地模型/云端调用都在插件里），只能干看着。

顺带确认过的事实：

- 宿主附件以**无扩展名的 blob** 落在 `~/.dsh/attachments/v1/objects/`，agent 拿到的是一串没有后缀的路径
- 解码用 PyAV 的 `av.open()`，**靠内容嗅探容器**，不依赖扩展名 —— 所以无后缀也能解
- 产物落点（会话工作区 `meetings/<id>.md`）已由上一 spec 打通

目标：新增一个工具，让 agent 能用**一句话**完成「导入音频 → 转写 → 拿到产物路径」，
之后它自己读写产物文件生成纪要（本版不做插件生成纪要）。

成功长什么样：在会话里丢一个 m4a（或给个本地路径），说「帮我整理成纪要」；
agent 调 `meeting_import` 一次，拿到产物文件的绝对路径，读进来，再把纪要写进文件的「## 纪要」段。

## 需求条款

### R-01 导入工具

WHEN agent 收到一段音频路径，
系统 SHALL 提供工具 `meeting_import({ path, label?, transcribe? })`，接受本地路径或宿主附件路径。

WHEN 调用该工具，
系统 SHALL 校验：路径非空、文件存在、是普通文件、大小不超过上限（默认 500 MB）。

边界：路径不存在或不是文件时，返回可读错误并指名字段；不得创建会议记录。

#### 验收场景

- **GIVEN** 一个存在的 45 MB m4a
  **WHEN** 调用 `meeting_import`
  **THEN** 导入成功，返回会议 id 与时长
- **GIVEN** 不存在的路径
  **WHEN** 调用
  **THEN** 返回「文件不存在」且没有新建会议

### R-02 无扩展名与容器嗅探

WHEN 传入的路径**没有扩展名**（宿主附件的常见形态），
系统 SHALL 仍能解码并取出时长，产物落盘时使用安全的后备扩展名（如 `.bin`），不因缺少后缀失败。

边界：真正的非音频文件必须给出「不是可识别的音频」的可读错误，而不是崩溃或静默 0 秒。

#### 验收场景

- **GIVEN** 无后缀的 m4a blob
  **WHEN** 导入
  **THEN** 时长正确（与带后缀时一致）
- **GIVEN** 一个纯文本文件改名为 `.m4a`
  **WHEN** 导入
  **THEN** 返回「不是可识别的音频」

### R-03 可选自动转写

WHEN `transcribe` 未显式关闭（默认开启），
系统 SHALL 在导入后立刻用**配置里的引擎**转写，并把转写写进产物单文件。

WHEN `transcribe: false`，
系统 SHALL 只做导入，返回音频路径，不触发转写。

边界：转写失败不回滚导入（会议与音频仍然可用），错误要能看出是「导入成功、转写失败」。

#### 验收场景

- **GIVEN** 配置为云端引擎
  **WHEN** 导入并自动转写
  **THEN** 返回段数 > 0、产物含 `## 转写`
- **GIVEN** 云端缺 Key
  **WHEN** 自动转写
  **THEN** 导入成功但返回转写失败原因（缺 Key），会议仍在列表里

### R-04 产物路径可直接用

WHEN 导入与转写完成，
系统 SHALL 返回**两个路径**：`outputPath`（相对工作区，给人看）与 `outputFile`（绝对路径，给工具用），
外加 `outputMode`（workspace / fallback）。

边界：agent 必须能用 `outputFile` 直接读写，不需要自己拼路径。

#### 验收场景

- **GIVEN** 会话有工作区
  **WHEN** 导入转写完成
  **THEN** `outputFile` 是绝对路径且文件存在，内容含元信息与转写
- **GIVEN** 会话无工作区
  **WHEN** 同上
  **THEN** `outputMode = fallback`，`outputFile` 指向数据目录下的同一结构文件

### R-05 幂等与命名

WHEN 同一个文件被导入两次，
系统 SHALL 创建两场独立会议（不覆盖前一场的产物），并在返回里体现不同的会议 id。

WHEN 未给 `label`，
系统 SHALL 用文件名（去掉后缀）作为标签；文件名不可用时用开始时间。

#### 验收场景

- **GIVEN** 同一路径导入两次
  **WHEN** 查看列表
  **THEN** 两条会议，产物文件不同
- **GIVEN** 未给 label 且文件名是 `周会录音.m4a`
  **WHEN** 导入
  **THEN** 标签为 `周会录音`

### R-06 与既有能力不冲突

WHEN 改造完成，
系统 SHALL 保持：既有 6 个工具行为不变、路由与产物结构不变、录音链路不受影响。

边界：新工具不得改变 `meeting_transcribe` 的语义（它是对已有会议重跑转写）。

#### 验收场景

- **GIVEN** 改造后的插件
  **WHEN** 调用 `meeting_transcribe`
  **THEN** 行为与改造前一致

### R-07 可测

WHEN 执行单测，
系统 SHALL 覆盖：路径校验与大小上限、无扩展名的后备命名、标签推导、自动转写分派（开/关）、
错误映射（不存在/非音频/超限）、导入后返回路径的两种模式。

边界：路径与命名逻辑为纯函数；IO 依赖可注入。

#### 验收场景

- **GIVEN** 路径 `/x/周会录音.m4a` 且未给 label
  **WHEN** 推导标签
  **THEN** 得到 `周会录音`
- **GIVEN** `transcribe: false`
  **WHEN** 导入
  **THEN** service 的转写函数未被调用（用假实现断言）

## Non-goals（范围外）

- **插件自己生成纪要**（用户明确：本版由 agent 读写文件，下一版再做）
- 浏览器拖拽/选择文件上传（不做 multipart）
- 批量导入多个音频
- 音频转码/压缩
- 断点续传

## 我正在做的假设

1. **agent 能拿到音频的本地路径**（附件 blob 路径或用户给的本地路径），本工具只接收路径，不处理上传。
2. 附件 blob 无扩展名，因此**容器靠 PyAV 嗅探**，落盘用 `.bin` 后备。
3. 自动转写默认开启（`transcribe` 缺省为 true）——因为「导入就是为了转写」，关掉是少数场景。
4. 大小上限默认 **500 MB**，超限直接拒绝而不是截断。
5. 产物沿用上一 spec 的单文件结构与返回约定（`outputPath` / `outputFile` / `outputMode`）。

现在纠正，否则按此执行。

## 待确认问题

- 无阻塞项。假设 1 与 2 是技术前提，Phase 2 会用真实附件路径探针验证（无扩展名的 blob 能否解码）。
