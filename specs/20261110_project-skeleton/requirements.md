# 需求规格：project-skeleton（会记项目骨架）

## 背景与目标

会记（dsh-note-taker）是「录音 → 本地转写 → 音色分人 → 结构化纪要」的 DSH 插件，方案见
`docs/dsh-note-taker-方案.md`。当前全部实现留在 `ai_dsh_test\dsh-note-taker`，不在版本控制内；
本仓库只有方案与台账。

用户于 2026-11-10 决定：**在本仓库重建骨架，旧目录归档不动**。本需求交付一个「可运行的骨架」——
不是设计稿，也不是全链路打通：

- 结构清楚：宿主侧、浏览器侧、Python sidecar 各层职责与契约写在明处，新人照 README 能跑起来
- 核心纪要逻辑是真的：转写文本解析、发言人统计、纪要素材包、成稿结构校验——都跑真、都有单测
- 页面管理是真的：DSH 插件化页面里能列出会议、看详情、发起动作，状态可回显

成功长什么样：`git clone` 后按 README 装好插件，DSH 里能打开「会记」页面看到空态；丢一份转写
文本进去能看到会议条目与转写详情；`npm run verify` 全绿。

## 需求条款

### R-01 骨架可作为 DSH 插件加载

WHEN DSH 以插件方式加载本仓库（profile 的 bundles 含 `dsh-note-taker`），
系统 SHALL 完成注册且不抛错：注册全部对外工具与 HTTP 路由，并在宿主日志留下一条启动记录
（含插件名、注册工具数、数据根路径）。

边界：加载失败 SHALL 降级为「本插件不可用」，不得让 web 壳启动失败。

#### 验收场景

- **GIVEN** 插件已加入 profile bundles
  **WHEN** 启动 DSH 并打开 web 界面
  **THEN** 宿主日志出现一条会记启动记录，界面正常可用，无插件报错
- **GIVEN** 数据根路径被配置成一个不可写的路径
  **WHEN** 启动 DSH
  **THEN** 插件报出可读的失败原因（含路径），界面其余部分照常可用

### R-02 分层结构与开发者文档

WHEN 开发者打开仓库根目录，
系统 SHALL 提供 `README.md`，至少包含：目录树、每层职责一句话、安装与本地调试命令、
数据目录位置与覆盖方式。

WHEN 执行仓库定义的校验命令（`npm run verify`），
系统 SHALL 校验骨架完整性（必需目录与文件齐全、清单与磁盘一致），并给出可读结果。

边界：清单里列出的文件缺失时，命令 SHALL 退出非零并指明缺哪一项。

#### 验收场景

- **GIVEN** 完整仓库
  **WHEN** 执行 `npm run verify`
  **THEN** 结构检查通过并输出检查项数量
- **GIVEN** 人为删除 `lib/index.js`
  **WHEN** 执行 `npm run verify`
  **THEN** 退出码非零，输出里点名 `lib/index.js` 缺失

### R-03 会议记录数据模型与持久化

WHEN 一次会议被登记（导入音频或手工创建），
系统 SHALL 以稳定数据模型落盘：会议 id、标签、开始与结束时间、时长、音频文件列表、
转写状态、纪要状态。

WHEN 进程重启后再次读取，
系统 SHALL 原样读回全部已登记会议，且顺序稳定（按开始时间倒序）。

边界：id 全局唯一；同一份音频重复登记 SHALL 被识别并提示，不产生重复条目。

#### 验收场景

- **GIVEN** 空数据目录
  **WHEN** 登记一次会议并重启进程
  **THEN** 列表中该会议仍在，字段与原值一致
- **GIVEN** 已登记某音频
  **WHEN** 用同一音频再次登记
  **THEN** 返回「已存在」并指向既有 id，列表条数不变

### R-04 转写文本解析（核心逻辑）

WHEN 提供一份符合本工具约定格式的转写文本（`[HH:MM:SS] 发言人：内容`，允许无发言人变体、
允许跨多行的同一条发言），
系统 SHALL 输出结构化记录：每条含起止时间、发言人（无则空）、正文；并给出统计
（发言人数量、每人发言段数与累计时长、整体覆盖时长）。

边界：格式不合法的行 SHALL 被指出行号与缺失项，不得静默丢弃或猜测。

#### 验收场景

- **GIVEN** 一份 3 人、40 分钟、含跨行发言的转写
  **WHEN** 解析
  **THEN** 记录条数与发言人统计正确，覆盖时长与末条时间一致
- **GIVEN** 某行时间戳写成 `[3:1]`（缺位）
  **WHEN** 解析
  **THEN** 返回错误，指出行号与期望格式，且不产出部分结果

### R-05 纪要素材包与成稿校验（核心逻辑）

WHEN 对一次已转写的会议请求生成纪要，
系统 SHALL 产出纪要素材包：会议元信息、完整转写、发言人统计、以及成稿必须包含的章节清单。

WHEN 收到一份按该结构写好的纪要成稿，
系统 SHALL 逐条校验章节完整性（标题、日期与时长、参会发言人、一句话摘要、议题、决议、行动项表），
列出缺失或空项；校验通过才写入 `minutes/` 并更新会议状态。

边界：行动项表为空时，成稿 SHALL 明写「本次无行动项」；缺失负责人或截止时间的行动项
SHALL 被标为待补，而非被丢弃。

#### 验收场景

- **GIVEN** 一份已转写会议
  **WHEN** 请求素材包
  **THEN** 返回内容含元信息、全文、统计与章节清单，且不包含任何模型提示词
- **GIVEN** 一份缺「决议」章节的成稿
  **WHEN** 提交校验
  **THEN** 返回未通过并点名缺「决议」，`minutes/` 下不产生文件

### R-06 会记页面：列表与详情

WHEN 用户在 DSH 中打开「会记」页面，
系统 SHALL 展示会议列表（时间、标签、时长、转写状态、纪要状态），并可选中一行查看详情
（元信息、转写正文、纪要正文）。

WHEN 列表为空，
系统 SHALL 展示空态与下一步指引（导入音频、开始录音）。

边界：页面数据一律经宿主侧接口取得，前端不直读磁盘；接口失败时页面展示可读错误，不得白屏。

#### 验收场景

- **GIVEN** 数据目录已有 3 次会议
  **WHEN** 打开页面
  **THEN** 三行按开始时间倒序显示，状态列与实际一致
- **GIVEN** 宿主侧接口全部失败
  **WHEN** 打开页面
  **THEN** 页面显示错误说明与重试入口，不出现白屏或未捕获异常

### R-07 页面上的动作入口与状态回显

WHEN 用户在页面上触发「导入音频并转写」「查看纪要素材」这类动作，
系统 SHALL 经宿主侧接口发起，并把状态（排队中 / 进行中 / 完成 / 失败）回显到该会议行。

边界：本版本未接入真实录音时，录音入口 SHALL 显示「未接入」并说明原因，不得静默无响应。

#### 验收场景

- **GIVEN** 页面与数据目录就绪
  **WHEN** 对一次会议触发转写
  **THEN** 该行状态先变为进行中，完成后变为已完成，无需刷新整页
- **GIVEN** 录音依赖缺失
  **WHEN** 点击录音入口
  **THEN** 显示「未接入」及缺失原因的字符串，页面不报错

### R-08 Agent 侧工具契约

WHEN Agent 调用会记工具（记录开始/停止、转写、纪要素材、会议列表），
系统 SHALL 返回结构化结果；失败时 SHALL 返回带错误码的错误
（`E_DEP` 依赖缺失 / `E_DEVICE` 无设备 / `E_MODEL` 模型缺失 / `E_AUDIO` 音频不可读 /
`E_STATE` 状态不允许），而不是裸异常或空字符串。

边界：每个工具的参数与返回字段 SHALL 在 README 与工具描述中一致地写明。

#### 验收场景

- **GIVEN** 转写依赖未安装
  **WHEN** Agent 调用转写工具
  **THEN** 返回 `E_DEP` 与缺失项名称，Agent 可据此给出修复指引
- **GIVEN** 传入不存在的音频路径
  **WHEN** Agent 调用转写工具
  **THEN** 返回 `E_AUDIO` 与路径，不抛出未捕获异常

### R-09 全程本地

WHERE 任何转写与纪要处理，
系统 SHALL 只在本机完成，不向任何外部服务发送音频或文本内容。

边界：默认零网络出站；若将来引入可选云端能力，必须由用户显式开启，本版本不引入。

#### 验收场景

- **GIVEN** 断网环境
  **WHEN** 完成一次解析与素材包生成
  **THEN** 功能正常，无网络请求失败导致的报错

### R-10 骨架可验证

WHEN 执行仓库定义的校验命令，
系统 SHALL 跑通核心逻辑单测（解析的正常/异常/边界、纪要校验的通过与不通过），
并输出真实结果（通过数与失败数）。

边界：不允许以 lint / 结构检查替代行为测试。

#### 验收场景

- **GIVEN** 完整仓库
  **WHEN** 执行 `npm run verify`
  **THEN** 输出结构检查结果与单测通过数，全部为绿
- **GIVEN** 人为改坏解析规则（如丢弃非法行）
  **WHEN** 执行 `npm run verify`
  **THEN** 单测失败并指出哪条断言未通过

## Non-goals（范围外）

- 真实录音采集（`soundcard`）、音色分人（sherpa-onnx）、模型下载：本版本只留契约与明确提示
- 旧目录 `ai_dsh_test\dsh-note-taker` 的迁移、改造或删除（归档不动）
- 实时字幕、会议中的边录边转
- Word 导出、与飞书/腾讯会议等第三方服务对接
- 纪要语义内容的自动生成（见假设 1）
- 里程碑发版流程（本 spec 完成后另走 M2/M3/M4）

## 我正在做的假设

1. **「核心纪要逻辑」= 确定性部分**：转写解析、发言人统计、纪要素材包、成稿结构校验与落盘由插件
   代码实现；摘要/决议/行动项这类语义内容由 Agent 调用现有 `meeting-minutes-pro` 技能产出，
   插件不内嵌提示词。若你要的是「插件内部直接调模型出稿」，请现在纠正。
2. **页面形态**：做成 DSH 设置区的「会记」页面（`settings.section` 插槽），并在会话输入框旁
   （`conversation.input.right`）放一个快捷入口；不做顶层独立导航页——当前插件机制里未见该插槽。
3. **转写路径**：本版本走「导入已有音频文件 → 本机 faster-whisper 转写」，音频采集不实现。
4. **数据目录**：默认 `~/.dsh/note-taker`，开发期用 `NOTE_TAKER_DATA` 覆盖（沿用既有约定）。
5. **技术栈**：宿主侧 Node ESM + Cordis；页面侧 React 18 + DSH 客户端插槽，与已装的
   `dsh-sessions-manager` 同构；浏览器侧产物需要构建步骤。

现在纠正，否则按此执行。
