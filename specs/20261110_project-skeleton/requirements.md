# 需求规格：project-skeleton（会记 · 基础链路）

## 背景与目标

会记（dsh-note-taker）是「录音 → 本地转写 → 会议纪要」的 DSH 插件，方案见
`docs/dsh-note-taker-方案.md`。旧实现在 `ai_dsh_test\dsh-note-taker`，不在版本控制内，已归档不动。

用户 2026-11-10 三次收窄范围，最终口径：**先把最基本那条路径实现出来——录音、识别文字、
整理出纪要**（「简报」即纪要）。骨架与目录结构要清楚，页面管理不在本版。

本 spec 交付一条能跑通的最小链路：会话里说「开始录音」→ 说话 → 「停了，出纪要」→
拿到一份落到磁盘、含议题/决议/行动项的纪要。

成功长什么样：录一段 2–3 分钟真实说话，转写与纪要都在 `~/.dsh/note-taker` 下生成，
`npm run verify` 全绿，全过程不需要联网录音、不需要第三方会议软件。

## 需求条款

### R-01 插件可加载并留启动记录

WHEN DSH 加载本插件，
系统 SHALL 完成注册（工具 + 依赖服务）并在日志留下一条启动记录，含插件名、注册工具数、数据根路径。

边界：加载失败 SHALL 降级为「本插件不可用」，不得让 web 壳启动失败。

#### 验收场景

- **GIVEN** 插件已加入 profile bundles
  **WHEN** 启动 DSH
  **THEN** 日志出现启动记录，界面正常，无插件报错
- **GIVEN** 数据根指向一个不可写路径
  **WHEN** 启动
  **THEN** 报出可读失败原因（含路径），其余功能不受影响

### R-02 会议数据模型与持久化

WHEN 一次录音开始，
系统 SHALL 立刻创建会议记录：id、标签、开始时间、状态；录音结束后补齐结束时间与时长。

WHEN 进程重启后读取，
系统 SHALL 原样读回全部会议，按开始时间倒序。

边界：id 全局唯一；同一音频文件重复登记 SHALL 被识别并指向既有 id，不产生重复条目。

#### 验收场景

- **GIVEN** 空数据目录
  **WHEN** 录音一次并重启
  **THEN** 会议仍在，字段与原值一致，排序正确
- **GIVEN** 已登记某 wav
  **WHEN** 再次登记同一 wav
  **THEN** 返回既有 id，会议总数不变

### R-03 录音采集

WHEN 请求开始录音，
系统 SHALL 从默认输入设备采集音频，落盘为 16kHz 单声道 wav。

WHEN 请求停止，
系统 SHALL 在 3 秒内完成收尾，返回时长与文件路径，且文件可被标准解码器读出。

边界：无可用设备或设备被占用 SHALL 返回 `E_DEVICE` 与说明；录音中途异常 SHALL 仍产出可解码文件或明确失败，不得留下半截损坏文件。

#### 验收场景

- **GIVEN** 麦克风可用
  **WHEN** 录 5 秒后停止
  **THEN** 产出 wav，采样率 16k、单声道、时长 5s±0.5s
- **GIVEN** 麦克风被禁用
  **WHEN** 请求录音
  **THEN** 返回 `E_DEVICE` 与设备名，无残留文件

### R-04 语音转写

WHEN 对一次已录音会议请求转写，
系统 SHALL 用本机模型产出转录（每段含起止时间与文本），落盘为 md 与 json，并在过程中把状态置为进行中、结束置为完成或失败。

边界：音频不可解码 → `E_AUDIO`；模型缺失 → `E_MODEL`；转写失败 SHALL 保留上一次成功结果不被覆盖。

#### 验收场景

- **GIVEN** 一段 60 秒中文录音
  **WHEN** 转写
  **THEN** 产出 md/json，段数 > 0，时间戳单调递增，状态为完成
- **GIVEN** 音频文件被截断损坏
  **WHEN** 转写
  **THEN** 返回 `E_AUDIO`，会议状态为失败且原有转写不变

### R-05 转写解析与统计（核心逻辑）

WHEN 解析一份转录文本（`[HH:MM:SS] 文本`，允许无时间戳变体、允许一条发言跨多行），
系统 SHALL 输出结构化段落与统计：段数、覆盖时长、字符数。

边界：格式不合法的行 SHALL 指出行号与期望格式，不得静默丢弃或猜测。

#### 验收场景

- **GIVEN** 含 3 段、其中 1 段跨 2 行的转录
- **WHEN** 解析
  **THEN** 3 段、覆盖时长等于末段结束时间、字符数等于各段正文之和
- **GIVEN** 某行写成 `[3:1] 内容`
  **WHEN** 解析
  **THEN** 返回错误并指出行号，不产出部分结果

### R-06 纪要生成（核心逻辑）

WHEN 对一次已转写会议请求纪要，
系统 SHALL 使用用户在 DSH 中已配置的模型生成纪要，结构固定包含：标题、日期与时长、
一句话摘要、议题、决议、行动项表（负责人、截止时间）。

WHEN 生成结束，
系统 SHALL 校验结构完整性，通过则落盘到 `minutes/` 并更新状态；不通过 SHALL 列出缺失项且不落盘。

边界：行动项为空 SHALL 明写「本次无行动项」；缺失负责人或截止时间的行动项 SHALL 标为待补；模型不可用 SHALL 返回 `E_MODEL` 且转写保持不动。

#### 验收场景

- **GIVEN** 一份 40 分钟会议转录
  **WHEN** 生成纪要
  **THEN** 产出含七个固定章节的 markdown，落盘路径可读，状态为完成
- **GIVEN** 模型返回缺「决议」章节的文本
  **WHEN** 校验
  **THEN** 不落盘，返回缺失项列表，会议纪要状态为失败

### R-07 工具契约与错误码

WHEN Agent 调用会记工具（录音起停、转写、纪要、列表、状态），
系统 SHALL 返回结构化结果；失败 SHALL 返回带错误码与可读说明的错误：
`E_DEP` 依赖缺失 / `E_DEVICE` 无设备 / `E_MODEL` 模型不可用 / `E_AUDIO` 音频不可读 /
`E_STATE` 状态不允许 / `E_LLM` 模型调用失败。

边界：不得抛裸异常或返回空字符串；每个工具的参数与返回字段 SHALL 与 README 一致。

#### 验收场景

- **GIVEN** 转写依赖未安装
  **WHEN** 调用转写工具
  **THEN** 返回 `E_DEP` 与缺失项名
- **GIVEN** 尚未录音
  **WHEN** 调用停止录音
  **THEN** 返回 `E_STATE`，进程不崩

### R-08 隐私边界

WHERE 音频与转写文本，
系统 SHALL 只在本机处理与存储，不发送给任何第三方服务。

WHEN 生成纪要，
系统 SHALL 把转写文本发送给用户在 DSH 中已配置的模型服务，并在首次生成前明确提示这一点。

边界：除该模型服务外，零网络出站；提示 SHALL 可查（日志与工具返回各留一次）。

#### 验收场景

- **GIVEN** 断网
  **WHEN** 录音与转写
  **THEN** 两者均正常，无网络相关报错
- **GIVEN** 首次生成纪要
  **WHEN** 请求
  **THEN** 返回内容里明确说明「转写文本将发送给已配置模型」

### R-09 骨架结构与开发者命令

WHEN 开发者打开仓库，
系统 SHALL 提供 `README.md`：目录树、每层职责一句话、安装步骤、常用命令、数据目录与覆盖方式。

WHEN 执行 `npm run verify`，
系统 SHALL 校验骨架完整性（必需文件齐全）并跑核心逻辑单测，输出真实结果。

边界：清单项缺失 SHALL 退出非零并点名缺哪一项。

#### 验收场景

- **GIVEN** 完整仓库
  **WHEN** 执行 `npm run verify`
  **THEN** 结构检查通过 + 单测全绿，输出检查项与通过数
- **GIVEN** 删除 `py/transcribe.py`
  **WHEN** 执行 verify
  **THEN** 退出非零并点名该文件

### R-10 核心逻辑单测

WHEN 执行 `npm run verify`，
系统 SHALL 跑真单测，覆盖转写解析（正常 / 跨行 / 非法行）与纪要结构校验（合格 / 缺章节 / 空行动项）。

边界：不得以 lint 或结构检查替代行为测试。

#### 验收场景

- **GIVEN** 完整仓库
  **WHEN** verify
  **THEN** 上述六类用例逐条有对应断言并全部通过
- **GIVEN** 人为把非法行改成静默丢弃
  **WHEN** verify
  **THEN** 对应用例失败并指出断言

## Non-goals（范围外）

- **页面 / UI**：含 DSH 插件化页面、录音按钮、会议列表页（转 BL-01）
- 音色分人（sherpa-onnx）、系统声 / loopback 录音（转 BL-02、BL-03）
- 实时字幕、边录边转
- Word 导出、飞书/腾讯会议等第三方对接
- 旧目录 `ai_dsh_test\dsh-note-taker` 的迁移与删除
- 里程碑发版（M2/M3/M4 另走）

## 我正在做的假设

1. **录音走宿主侧 Python**（离线 wheel 安装采集库），不做浏览器 `getUserMedia`：
   后者要建客户端构建链（React + 打包），且 Electron 下麦克风权限尚未验证。
2. **纪要由 DSH 已配置模型生成**（`ctx.llm.stream`），插件负责结构化提示、校验与落盘；
   不在插件里做本地模板拼装冒充摘要。
3. **数据目录** `~/.dsh/note-taker`，开发期用 `NOTE_TAKER_DATA` 覆盖；从第一版就支持覆盖。
4. **默认转写模型 `small`**（本机可用内存 3.1–3.3 GB，`medium` 作可选档）。
5. **录音设备**取系统默认输入设备，本版不做设备选择。
6. 页面管理、分人、系统声录音已记入 backlog（BL-01/02/03），不是本 spec 的欠账。
