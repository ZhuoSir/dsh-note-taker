# 任务清单：project-skeleton（会记 · 基础链路）

## 1. 基础骨架

- [ ] T-01 建立仓库骨架与插件入口
  关联: R-01, R-09
  依赖: 无
  验证方式: `npm run verify` 的结构检查段通过（清单含 package.json / cordis.patch.yml / lib/index.js / py/record.py / py/transcribe.py / README.md），且 `node -e "import('./lib/index.js').then(m=>console.log(m.name, m.inject))"` 输出插件名与 `['tools','llm']`
  日志断言: 用 `fake` ctx 调一次 `apply()`，捕获日志必须出现「插件启动」一行，含插件名、工具数、数据根路径
  验收标准: 结构检查绿；入口可被 import 且 name/inject/apply 三个导出一应俱全

- [ ] T-02 实现会议存储与原子写
  关联: R-02
  依赖: T-01
  验证方式: `node --test tests/meetings.test.js` 通过，用例覆盖：新增后读回字段一致、重启（重新实例化）后仍可读、按 startedAt 倒序、同一 wav 的 sha256 重复登记返回既有 id、meetings.json 损坏时报错不静默重置
  日志断言: 重复登记命中时日志出现「会议去重」一行，含新 id 与命中 id
  验收标准: 六类用例全绿；写入过程无 `.tmp` 残留

## 2. 核心逻辑（纯函数，单测主战场）

- [ ] T-03 实现转写解析与统计
  关联: R-05
  依赖: T-01
  验证方式: `node --test tests/parse.test.js`，用例覆盖：标准 `[HH:MM:SS]` 格式、无时间戳变体、一条发言跨两行、末段时间=覆盖时长、非法时间戳 `[3:1]` 报错并给行号、空输入返回空集合而非抛错
  验收标准: 六类用例全绿；解析器零外部依赖（不 import 任何 node 模块以外的包）

- [ ] T-04 实现纪要结构校验器
  关联: R-06
  依赖: T-01
  验证方式: `node --test tests/minutes-validate.test.js`，用例覆盖：七章节齐全判合格、缺「决议」判不合格并点名、行动项表为空但写明「本次无行动项」判合格、行动项缺负责人被判出待补项
  验收标准: 四类用例全绿；校验器对输入只读，不修改内容

## 3. 音频链路

- [ ] T-05 接入录音 sidecar（含离线依赖安装）
  关联: R-03, R-07
  依赖: T-01
  验证方式: 按 L-02 离线安装采集库后，`node scripts/smoke-record.mjs` 录 5 秒：产出 wav 能被 `python -c "import av; ..."` 读出，采样率 16000、单声道、时长 5s±0.5s；把设备名改成不存在的设备，返回 `E_DEVICE` 且不残留文件
  日志断言: 冒烟脚本日志必须出现「录音开始」（含设备名、采样率、目标路径）与「录音结束」（含时长、字节数、退出码）；失败路径出现「录音失败」含错误码与 stderr 尾部
  验收标准: 正常路径产出合规 wav；异常路径返回 `E_DEVICE` 且目录无残留

- [ ] T-07 接入转写 sidecar
  关联: R-04
  依赖: T-01
  验证方式: 用 T-05 产出的 wav 跑 `python py/transcribe.py --audio <wav> --out-dir <tmp>`，产出 md + json，json 内 segments 数 > 0 且 start 单调递增；把 wav 头部截断后再跑，退出码非零且 stderr 含可读原因
  日志断言: 转写日志出现「转写开始」（含模型、音频时长）与「转写结束」（含段数、rtf、耗时）；失败路径出现「转写失败」含错误码与 stderr 尾部
  验收标准: 正常与损坏两路行为符合 R-04 边界；失败不覆盖已有 transcript 文件

## 4. 编排与工具

- [ ] T-06 验证 llm 调用并实现纪要生成
  关联: R-06, R-08
  依赖: T-04
  验证方式: 先写 `scripts/smoke-llm.mjs` 用 `ctx.llm.stream` 打一次最小请求并打印首尾字符（确认参数形状）；再实现 `lib/minutes.js` 后，用一份固定转录跑出纪要，校验器判合格并落盘；把模型返回替换成缺「决议」的文本，确认不落盘且列出缺失项
  日志断言: 日志必须出现「纪要生成开始」（provider、model、输入字符数）与「纪要生成结束」（耗时、输出字符数、校验结果）；构造缺章节场景时出现「纪要校验不通过」并列出缺失章节
  验收标准: 真实模型跑通一次并落盘；缺章节场景不落盘、状态为 failed

- [ ] T-08 注册全部工具与状态机
  关联: R-01, R-07
  依赖: T-02, T-05, T-07
  验证方式: `npm run verify` 中工具清单断言：注册数 == 6 且名字集合精确匹配；逐个调用失败路径：未录音时 stop → `E_STATE`；未转写时 minutes → `E_STATE`；不存在的 meetingId → `E_STATE`，且进程不退出
  日志断言: 每次状态迁移写一行「状态迁移」，含 meetingId、字段名、旧值 → 新值；并发调用第二个录音必须出现「拒绝并发」一行
  验收标准: 六个工具全部注册；四类错误路径返回结构化错误码；无未捕获异常

- [ ] T-09 统一错误信封与隐私提示
  关联: R-07, R-08
  验证方式: `node --test tests/errors.test.js` 断言每个错误码至少有一条触发用例且返回 `{ok:false,code,message}`；`meeting_minutes` 首次调用返回的 `notice` 字段包含「转写文本将发送给已配置模型」字样，且日志同轮出现一次
  验收标准: 六类错误码均有用例覆盖；隐私提示在返回值与日志各出现一次

## 5. 验证收尾

- [ ] T-10 单测收口与 verify 脚本
  关联: R-10, R-09
  验证方式: `npm run verify` 一次跑完：结构检查 → 全部单测，输出通过数与失败数；人为把解析器改成静默丢弃非法行，确认对应用例失败并指出断言
  验收标准: 全绿；人为破坏能被测出；verify 退出码与结果一致
  日志断言: 不适用（纯校验脚本，无副作用）

- [ ] T-11 端到端演练：录音 → 转写 → 纪要
  关联: R-03, R-04, R-06
  依赖: T-08, T-09
  验证方式: 真人说 2–3 分钟（含 1 个明确决议和 2 个带负责人的行动项），走完成链路，把产物路径、时长、rtf、纪要正文首 20 行贴进 completion.md；再次执行 verify 确认无回归
  验收标准: 三份产物齐备（wav/transcript/纪要）；纪要含七章节且行动项与口述事实一致；rtf 与耗时如实记录
  日志断言: 整条链路日志按序出现「录音开始/结束」→「转写开始/结束」→「纪要生成开始/结束」，无 ERROR 行
