# 需求规格：meeting-console（会记工作台）

## 背景与目标

上一个 spec（meeting-page）把「页面基础设施」建起来了：插槽、路由、构建链、宿主适配全部打通。
但页面职责是按「列表 + 详情 + 动作一把抓」设计的，实际用起来不是用户想要的形状。

用户 2026-11-10 明确了两件事：

1. **设置区「会记」是配置页**——模型参数、路径、Key、选云端还是本地 ASR；顺带能翻历史会议纪要。
2. **真正干活的是会话输入框旁那个卡片**——录音、停下来、识别成文字、**由人确认**，确认后**交给会话**去生成纪要。

目标：把这两件事各归各位，形成「配置一次 → 开会时点一下 → 看一眼确认 → 会话出纪要」的闭环。

成功长什么样：设置里填一次 Key 和引擎；开会点「开始录音」，散会点「停止」；几十秒后弹出转写文本，
扫一眼改两个错字，点「交给会话」；对话里立刻出现一条消息，agent 据此产出会议纪要文件。

## 需求条款

### R-01 设置页：配置可读写

WHEN 用户在设置区打开「会记」，
系统 SHALL 提供可编辑的配置项：数据目录、云端 API Key、云端接口地址、云端模型名、
默认 ASR 引擎（本地/云端）、本地模型档位、长音频分片秒数。

WHEN 用户保存，
系统 SHALL 校验取值（路径可写、秒数为正整数、引擎枚举合法），保存成功后立即反映在页面上。

边界：不能保存非法值；校验失败要指出**哪个字段**错了，不能只说「保存失败」。

#### 验收场景

- **GIVEN** 分片秒数填 `0`
  **WHEN** 保存
  **THEN** 提示「分片秒数必须是 10–3600 的整数」且不落盘
- **GIVEN** 填入合法 Key
  **WHEN** 保存并刷新页面
  **THEN** Key 以掩码形式回显（如 `sk-…abcd`），不出现明文

### R-02 配置优先级与持久化

WHEN 解析配置，
系统 SHALL 按 **页面保存的配置 > 环境变量 > 内置默认** 的优先级合并。

WHEN 保存数据目录，
系统 SHALL 明确提示「需重启宿主生效」，并说明其余项可热生效。

边界：页面配置存于数据目录内的 JSON 文件，不得写入密钥明文到日志；文件不存在时按环境变量与默认值工作。

#### 验收场景

- **GIVEN** 环境变量设了 Key，页面又保存了另一个 Key
  **WHEN** 发起云端转写
  **THEN** 使用页面保存的那个
- **GIVEN** 页面从未保存过
  **WHEN** 查看配置
  **THEN** 显示环境变量的值（有则显示掩码，无则空）

### R-03 引擎选择贯穿全链

WHEN 用户在设置里选择默认引擎，
系统 SHALL 让录音流程的自动转写使用该引擎；云端引擎不可用时回退提示而不是静默改用本地。

边界：云端缺少 Key 时，卡片上的录音按钮仍可用（录音是本地行为），但停止后 SHALL 明确提示「云端不可用，需配置 Key」或改用本地（由配置决定，不猜）。

#### 验收场景

- **GIVEN** 默认引擎=cloud 且未配 Key
  **WHEN** 停止录音
  **THEN** 提示缺少 Key 与配置入口，不产出转写
- **GIVEN** 默认引擎=local 且本地模型未下载
  **WHEN** 停止录音
  **THEN** 提示模型未下载

### R-04 历史纪要列表（只读）

WHEN 用户打开设置页，
系统 SHALL 列出**已生成纪要**的会议：时间、标签、时长、引擎、段数/字数，按时间倒序。

WHEN 用户点开一条，
系统 SHALL 展示该纪要的 Markdown 正文。

边界：只读——本版不提供删除、编辑、重命名；没有纪要时显示空态并提示「录音后由会话生成」。

#### 验收场景

- **GIVEN** 3 场会议中只有 1 场有纪要
  **WHEN** 打开设置页
  **THEN** 列表只显示那 1 场
- **GIVEN** 点开该条
  **WHEN** 纪要文件存在
  **THEN** 正文完整显示（长文可滚动）

### R-05 录音工作流（会话卡片）

WHEN 用户在会话输入框旁点击「会记」，
系统 SHALL 提供：开始录音、录音计时、停止录音。

WHEN 停止录音，
系统 SHALL 自动用配置的引擎转写，并在完成后把**转写文本放进可编辑的确认区**。

WHEN 用户确认，
系统 SHALL 使用确认后的文本进行交接（允许用户改错字）。

边界：转写失败要在卡片上直接看到原因并可重试；确认区关闭后再打开仍能看到最近一次结果。

#### 验收场景

- **GIVEN** 录了 10 秒
  **WHEN** 点停止
  **THEN** 卡片显示「识别中…」，完成后出现可编辑文本框与「交给会话」按钮
- **GIVEN** 识别失败（如 Key 无效）
  **WHEN** 停止录音
  **THEN** 卡片显示失败原因与「重试」按钮

### R-06 交给会话生成纪要

WHEN 用户点「交给会话」，
系统 SHALL 把一条消息发送进**当前会话**，内容包含：会议基本信息（标签/时长/会议 id）、
「请据此生成会议纪要」的指令，以及确认后的转写正文。

WHEN 发送成功，
系统 SHALL 在卡片上给出「已发送，等待会话生成」的反馈，并保留该会议 id 便于追溯。

边界：发送失败必须可见且可重试；不得静默吞掉。发送前 SHALL 明确告知「转写正文将作为消息发进当前会话」。

#### 验收场景

- **GIVEN** 确认区有 500 字转写
  **WHEN** 点「交给会话」
  **THEN** 当前会话出现一条用户消息，含会议 id 与转写正文，且卡片显示已发送
- **GIVEN** 宿主不支持发送接口
  **WHEN** 点「交给会话」
  **THEN** 退化为「填入输入框」并说明原因，不假装已发送

### R-07 状态可见与刷新保持

WHEN 录音或转写在跑，
系统 SHALL 在卡片上显示进行中状态与已用时间；关闭面板再打开、或刷新页面后，
状态 SHALL 仍能从服务端恢复。

边界：不得出现「界面显示进行中但服务端已失败」的长期不一致（一个轮询周期内纠正）。

#### 验收场景

- **GIVEN** 一次云端转写进行中
  **WHEN** 刷新页面并重新打开卡片
  **THEN** 仍显示「识别中」
- **GIVEN** 后台已失败
  **WHEN** 下一轮询
  **THEN** 显示失败与原因

### R-08 配置与消息的安全边界

WHEN 读取配置，
系统 SHALL 只返回 Key 的掩码，**任何接口/日志都不得返回或记录明文 Key**。

WHEN 保存配置，
系统 SHALL 只接受白名单键；未知键被忽略并告警。

边界：配置写入文件权限收到仅本人可读；接口只监听回环地址（沿用上一 spec 的约束）。

#### 验收场景

- **GIVEN** 调用配置读取接口
  **WHEN** 检查响应
  **THEN** 不含完整 Key，只含掩码
- **GIVEN** 提交含未知键的配置
  **WHEN** 保存
  **THEN** 未知键被忽略，响应中列出被忽略的键

### R-09 既有能力不回归

WHEN 本次改造完成，
系统 SHALL 保持：命令行工具（`meeting_*`）、转写产物格式、纪要生成校验、云端/本地双引擎行为不变。

边界：设置页不再承担「发起转写/生成纪要」这类动作（改由会话完成），但底层 service 能力保留。

#### 验收场景

- **GIVEN** 改造后的插件
  **WHEN** 在会话里调用 `meeting_transcribe`
  **THEN** 行为与改造前一致

### R-10 可测：纯逻辑 + 路由 + 渲染 + 交接构造

WHEN 执行单测，
系统 SHALL 覆盖：配置合并与优先级、Key 掩码、字段校验、纪要列表筛选、交接消息构造（含会议 id 与正文）、
路由的读写与错误映射、两个组件的渲染回归。

边界：交接消息的构造必须是纯函数，可单测，不依赖宿主。

#### 验收场景

- **GIVEN** 会议 id、标签、时长、转写文本
  **WHEN** 构造交接消息
  **THEN** 文本含 id 与「生成会议纪要」指令，且正文原样保留
- **GIVEN** Key 为 `sk-1234567890abcdef`
  **WHEN** 掩码
  **THEN** 结果为 `sk-…cdef`（既不能全露也不能全遮到无法辨识）

## Non-goals（范围外）

- 多用户、权限、远程访问
- 会议删除/归档/重命名/合并
- 纪要在线编辑（本版纪要由会话生成并落盘，页面只读）
- 实时字幕（边说边出）
- 说话人重命名
- 配置的跨机器同步

## 我正在做的假设

1. **配置存 `<数据目录>/config.json`**（JSON，权限尽力收窄），优先级 页面 > 环境变量 > 默认。
2. **需要重启的只有数据目录**；Key / 接口地址 / 模型名 / 引擎 / 分片秒数 可热生效（每次请求重新解析）。
3. **交接用客户端 `conversation.send(text)`**（已查到宿主 `dsh-client-ui-conversation` 暴露该方法）；
   若在插件上下文不可用，则退化为「填入输入框 + 提示原因」，不假装成功。
4. 历史纪要列表复用现有 `/note-taker/list` 与 `/detail`，页面侧按「有纪要」过滤。
5. 用户在确认区改过的文本**只用于交接**，不回写 `transcripts/*.md`（避免污染原始转写）。
6. 纪要仍由会话里的 agent 调用 `meeting_minutes` 或直接产出，**页面不落纪要文件**。

现在纠正，否则按此执行。
