# 需求规格：meeting-workspace-output

## 背景与目标

现在转写与纪要都写在插件自己的数据目录里：

```
<数据目录>/transcripts/<id>.md
<数据目录>/minutes/<id>.md      （数据目录默认 ~/.dsh/note-taker，可用 NOTE_TAKER_DATA 覆盖）
```

而用户实际是在**会话**里干活——agent 的工作目录是当前会话的工作区。
于是出现割裂：纪要生成在一个 agent 默认看不见的地方，交接消息只能把正文**整段塞进对话**，
47 分钟的转写就是一万五千字，既费 token 又碍阅读。

用户 2026-11-10 提出：**纪要写进当前会话的工作区，交接时直接引用那个 md 文件**。

目标：产物落在 agent 能直接读到的地方；交接消息从「贴全文」变成「给路径 + 关键摘要」。

成功长什么样：开完会点「交给会话」，会话里出现的是一条简短消息——会议 id、时长、纪要文件路径，
agent 打开 `<工作区>/meetings/<id>.md` 就能读到完整转写并据此产出纪要。

## 需求条款

### R-01 产物写入会话工作区

WHEN 一次录音被识别（或音频被导入后识别），
系统 SHALL 把转写与后续纪要写入**当前会话工作区**下的 `meetings/` 子目录，文件名 `<会议id>.md`。

WHEN 产物写入完成，
系统 SHALL 在结果中回传该文件相对工作区的路径（如 `meetings/20261110-1626-3d64.md`）。

边界：拿不到会话工作区时，必须回落到原数据目录并**明确告知**回落事实，不得静默丢弃产物。

#### 验收场景

- **GIVEN** 会话工作区为 `D:\work\demo`
  **WHEN** 识别完成
  **THEN** 文件写入 `D:\work\demo\meetings\<id>.md`，且返回相对路径
- **GIVEN** 会话没有工作区（未指定目录）
  **WHEN** 识别完成
  **THEN** 写入数据目录，并在结果与界面显示「会话无工作区，已存到数据目录」

### R-02 单个文件承载转写与纪要

WHEN 生成纪要，
系统 SHALL 把「会议元信息 + 转写全文 + 纪要正文」写进同一个 `<id>.md`（纪要部分可多次覆盖更新）。

边界：纪要重新生成时只替换纪要段落，**不得丢掉转写**；文件内的结构必须稳定可解析。

#### 验收场景

- **GIVEN** 已有转写的 `<id>.md`
  **WHEN** 生成纪要
  **THEN** 同一文件出现「纪要」段落，转写段落原样保留
- **GIVEN** 重新生成纪要两次
  **WHEN** 检查文件
  **THEN** 只有一份纪要段落，且是最后一次内容

### R-03 交接消息改为引用文件

WHEN 用户点「交给会话」，
系统 SHALL 发送一条**简短**消息，包含：会议 id、标签、时长、产物文件路径，
以及「请读取该文件并生成纪要」的指令——**不再内联整段转写**。

边界：消息长度与转写长度无关；文件路径必须是 agent 能直接打开的路径（绝对或相对工作区）。

#### 验收场景

- **GIVEN** 47 分钟会议
  **WHEN** 点交给会话
  **THEN** 消息正文 < 500 字，含 `meetings/<id>.md` 路径
- **GIVEN** 产物写在数据目录（回落）
  **WHEN** 点交给会话
  **THEN** 消息里的路径是绝对路径，agent 可直接打开

### R-04 与既有产物保持一致

WHEN 改造完成，
系统 SHALL 保持：命令行工具行为、`transcripts/*.md` 的段落格式（`[HH:MM:SS] 正文`）不变；
数据目录里不再重复写同一份内容（除非回落场景）。

边界：不能让「同一场会议两份不同内容的产物」并存，导致 agent 读到旧版。

#### 验收场景

- **GIVEN** 工作区可用
  **WHEN** 识别完成
  **THEN** 数据目录中不产生同名的转写副本
- **GIVEN** `meeting_transcribe` 工具在会话里被调用
  **WHEN** 检查
  **THEN** 返回的路径指向工作区产物

### R-05 回落与异常可见

WHEN 写入失败（权限不足、目录不存在、磁盘满），
系统 SHALL 明确报错并指出目标路径，且不产生半截文件。

边界：失败不得阻塞录音与识别本身；已识别的内容必须可再写一次。

#### 验收场景

- **GIVEN** 工作区只读
  **WHEN** 识别完成写文件
  **THEN** 返回可读错误含目标路径，界面显示，且转写仍可从数据目录取回

### R-06 可测

WHEN 执行单测，
系统 SHALL 覆盖：工作区路径解析（含拿不到时的回落）、单文件结构（元信息/转写/纪要段落合并）、
纪要覆盖不丢转写、交接消息构造（引用路径而非全文）、写入失败的错误映射。

边界：路径解析与文件结构合并必须是纯函数或可注入 IO 的函数。

#### 验收场景

- **GIVEN** 已有含转写的文件内容
  **WHEN** 合并新纪要段落
  **THEN** 结果里转写段落逐字未变
- **GIVEN** 文件路径为绝对路径
  **WHEN** 构造交接消息
  **THEN** 消息里保留绝对路径不缩写

## Non-goals（范围外）

- 不做多会话共享同一份产物（一场会议只属于一次识别的会话）
- 不做工作区外的云同步/导出
- 不改录音文件的落点（录音仍在数据目录，属隐私与容量考量）
- 不做纪要模板选择

## 我正在做的假设

1. **会话工作区路径可从宿主取到**（`dsh-workspace` 有「读会话 canonical 目录」的能力，`dsh-session` 有 `cwd`）；
   客户端通过 `sessions.scope(sessionId)` 作用域向宿主查询。
2. 产物放在 `<工作区>/meetings/`，目录不存在时自动创建。
3. 「转写 + 纪要」合成**一个文件**（`<id>.md`），用固定小标题分段（`## 转写` / `## 纪要`）。
4. 数据目录仅在**回落**时使用，正常路径下不再写副本。
5. 交接消息走既有的 `sessions.scope(id).get('conversation').send`，只是内容变短。
6. 录音文件（wav/m4a）**不**迁到工作区，仍留数据目录。

现在纠正，否则按此执行。
